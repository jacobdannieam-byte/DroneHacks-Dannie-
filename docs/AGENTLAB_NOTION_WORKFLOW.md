# Notion-centered strategy workflow

Notion is the shared research notebook and operational record. Git holds executable source; immutable artifacts hold measured evidence. Cross-link all three. Existing pages in agentlab/strategy_policy.json are the starting points; do not create competing strategy trackers.

## Work order

1. S1 Classical: preserve the physically tested baseline confirmed by the team. Inventory revision, settings and evidence; do not reinterpret a separate experimental failure as baseline failure.
2. S0 existing semantic-predictive Hybrid: reconcile source, inputs, ownership, integration blockers and comparison fixtures.
3. S2 active perception: test information gain and navigation consequences against S0 and S1.
4. S3 learned goal ranking: compare with the simpler S2 approach, retaining negative results.
5. S4 physics-informed prediction: evaluate nominal and shifted dynamics, downstream decisions and compute budgets.
6. New strategies: only after every existing strategy has an evidence-backed review disposition. Completion or flight qualification is not required to defer an unsuitable candidate, but an unexplained blocked task does not open this gate. Research supporting existing strategies is allowed throughout.

## Each work item

Read the strategy tracker, relevant roadmap/P2 sections, prior issues and experiments. Save source page IDs, retrieval time, content hashes and truncation flags. Reconcile claims against Git revisions and artifacts. Unknown or conflicting status becomes an issue; do not silently overwrite history.

Maintain linked records for research (primary sources, hypothesis, applicability), strategy (input/reasoning/output contracts), integration (branch/SHA, changed interfaces, tests), issues (reproduction, classification, owner if known, next action), experiments (matched configuration, all outcomes and hashes), decisions (adopt/evaluate/defer/reject and rationale). Never invent owners or successful runs. Every new proposal links its Notion issue and specifies acceptance and rejection criteria against S1.

The current repository provides pure planning validation and role instructions. Context acquisition and record publication are not automatically scheduled. The existing Notion publisher remains off; generated records remain drafts until separately authorized. This change does not activate workers, loops, simulations or physical flights.
